# Domain documentation

This repository has one domain context.

- Read root `CONTEXT.md` before discussing domain behavior. It is a glossary, not a feature specification or implementation plan.
- Create `docs/adr/` only when a hard-to-reverse, surprising decision involves a real trade-off. Read relevant ADRs if they exist; proceed without ceremony when they do not.
- Use the glossary's terms consistently in code discussions and issue titles. Clarify conflicting or overloaded terms with the user.
- Record newly agreed terms in the glossary when they crystallize. Keep v1 scope on the GitHub wayfinder map and detailed investigation resolutions on their child tickets.
