## Authentication

EAS CLI is already logged in. Appetize credentials live outside the repository in `~/.config/secrets/appetize` with `APPETIZE_API_TOKEN`. `scripts/appetize.sh` loads them without echoing them. It also accepts an existing environment token or `APPETIZE_SECRETS_FILE` override. Never print this file or commit session state.

## Build the native client

```sh
npm run check
npx expo-doctor
npm run build:sim -- --non-interactive --no-wait
```

Wait for EAS status FINISHED; download the simulator `.tar.gz` artifact from EAS. Device `.ipa` files do not run in Appetize.

```sh
./scripts/appetize.sh build upload artifacts/photo-pruner-simulator.tar.gz --wait
```

Save the returned build id. Any native Swift change, native dependency change, or Info.plist change requires a fresh build and upload. JavaScript changes use the current compatible client with Metro.

## Run and control

```sh
./scripts/start-dev.sh
./scripts/appetize.sh session start ipadpro129inch5thgeneration BUILD_ID --device-os-version 26.0 --session-id photo-pruner-loop > artifacts/appetize-session.json
./scripts/appetize.sh inspect evidence/launch.json
./scripts/appetize.sh screenshot evidence/launch
```

The startup script runs a Cloudflare Quick Tunnel and Metro together. It downloads the pinned Linux amd64 tunnel binary into ignored `artifacts/` if needed, checks its SHA-256, and stops its tunnel when Metro exits. Expo's bundled ngrok tunnel connected initially but failed repeatedly during verification; the separate tunnel completed the later checks. The experimental Expo V2 tunnel also failed and is not used. Quick Tunnels are temporary development endpoints ([Cloudflare documentation](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/do-more-with-tunnels/trycloudflare/)).

Before starting a billable simulator session, check `curl --fail TUNNEL_URL/status` returns `packager-status:running`. Keep the development server running. Connect the simulator with:

```sh
node scripts/connect-simulator.mjs TUNNEL_URL
./scripts/appetize.sh rotate landscapeLeft
```

This opens Enter URL manually, fills the URL, connects, and dismisses first-launch onboarding. It also disables Expo's floating Tools button, which otherwise overlaps Rescan. If needed, turn that button off in the native development menu manually. Use the app's Open folder button or Sample shoot.

```sh
./scripts/appetize.sh tap --select-test-id sample-folder
node scripts/press-keys.mjs artifacts/appetize-session.json 5 y ArrowLeft
./scripts/appetize.sh inspect evidence/review.json --select-test-id stars-value
./scripts/appetize.sh screenshot evidence/review
```

Always inspect before an unfamiliar action and verify afterward. Screenshots and recordings belong under `evidence/` (ignored by git). Use test IDs in our app. If system UI has no useful selector, use coordinates derived from a current screenshot.

`appetize type` pastes ordinary characters; it did not trigger the native Y/N/star shortcuts. `press-keys.mjs` uses the CLI viewer's local WebSocket keyboard transport, matching the installed Appetize CLI 0.16.0. This protocol is an implementation detail: recheck it when upgrading the CLI. Close other browser viewers before using it. The script reports event delivery; verify the resulting UI separately.

For a fresh sample shoot with no prior decisions, `node scripts/verify-ui.mjs` checks pairing metadata, rating, keep/reject, undo, persistence after rescanning, and the unreadable-RAW state. It writes assertions and screenshots to `evidence/`. The initial keyboard keep/rating demo above is compatible with this sequence, but an already rejected second photo is not. Native Files-provider popovers sometimes have sparse accessibility trees and require screenshot-driven interaction.

```sh
./scripts/appetize.sh recording start evidence/demo
# interact with the app
./scripts/appetize.sh recording stop
./scripts/appetize.sh session stop
```

Stop verification sessions promptly. Appetize session duration and minutes are account-limited. Do not assume data survives starting a fresh cloud session; test saved reviews by reloading/relaunching within the same session.

Press `r` in the Metro terminal for a full JavaScript reload. To verify Fast Refresh, change `src/revision.ts` and observe the footer marker without reconnecting or rebuilding. Desktop React Native DevTools installation emitted an Electron/root warning on this server; it did not prevent Metro, native logs, or Appetize inspection.

## Physical iPad

EAS knows the Apple team and the registered iPad. Creating a new app's internal-distribution credentials requires interactive setup; the non-interactive device-build attempt could not find suitable credentials.

```sh
eas build --platform ios --profile development-device
```

Complete Apple authentication and signing setup, select the registered iPad, and install the resulting build using its EAS link. Enable Developer Mode on the iPad if needed. Connect it to the same Metro tunnel using the development client. Apple credentials are not required for simulator builds.

## What lives where

- `src/domain/library.ts`: grouping, command behavior, undo, validated review serialization.
- `App.tsx`: native UI and asynchronous preview/persistence orchestration.
- `modules/photo-pruner-native`: folder picker, security-scoped bookmark, coordinated reads, ImageIO preview cache, atomic app-local review writes, hardware key commands.
- `src/revision.ts`: visible marker used to prove an actual source change reaches the simulator.
- `artifacts/`: local build metadata and downloads; excluded from git/EAS uploads.
